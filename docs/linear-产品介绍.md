# Linear：读懂这个产品

> 一份用大白话写的 Linear 平台介绍——帮你看懂它**是什么、给谁用、为什么这样设计、怎么用起来**。需要逐字施工级规格的，去看同目录的 `linear-behavior-spec.md`。

---

## 它是什么

Linear 是给软件团队用的**项目与任务管理工具**。如果你听说过 Jira——Linear 就是"反 Jira"：不为经理做报表，而是**为真正干活的人**（工程师、设计师、产品经理）做的。

2019 年立项、2020 年公开，创始团队是几个前 Airbnb / Uber / Stripe 的设计师和工程师（Karri Saarinen、Tuomas Artman、Jori Lallo）。他们做它的理由很直接：市面上的工具又慢又丑又官僚，工程师不想打开，于是任务系统里的信息永远滞后、永远不准。Linear 的目标只有一个——**做一个让人愿意主动打开的工具**。它的判断是：只要工具够快、够顺手，干活的人自己就会更新状态，信息自然就准了。

客户从初创公司到 OpenAI、Ramp、Vercel、Cash App 这种，**工程文化强的团队尤其爱用**。

---

## 它解决的真问题

大多数软件团队都有同一个困局：代码在 GitHub 和编辑器里，任务却躺在另一个又慢又重的系统里。填字段像写公文，状态没人愿意更新，经理只能靠催，催到最后大家糊弄。

Linear 的看法是——问题不在"流程不规范"，而在**"工具太难用"**。所以它不堆流程，而是把两件事做到极致：

- **速度**：秒开、键盘流、实时同步，打开它不觉得烦。
- **预设好的工作流**：它替你想好了"正确用法"，照着走就高效，不让你自由到乱套。

---

## 它的脾气：四条产品信念

Linear 是个**有主见**的工具。理解它的脾气，比记功能更重要：

1. **为创造者优化，不为报表优化。** 这是总纲。当"让经理看清进度"和"让工程师少点几下"冲突时，它永远选后者。
2. **预设优于自由。** 它故意不给无限自定义——优先级就 5 档、状态就那几类、工作流给你默认值。刚上手会觉得被限制，团队一大你就懂了：自由等于混乱，预设等于高效。
3. **键盘优先。** 整个产品按"高手用键盘飞起来"设计。建任务、改状态、跳转、搜索，熟练后几乎不用碰鼠标。这是它"快"的真正来源。
4. **写任务，不写 user story。** Linear 公开认为 user story 是"过时的仪式"——任务就该用大白话写清楚"要做什么"，描述能省则省，直接贴用户原话比概括强。

---

## 核心心智模型：工作分三层

Linear 把工作从大到小分成三层。**记住这张图，整个产品就通了**：

- **倡议（Initiative）**——公司或大团队的方向。比如"今年主攻企业版"。它把好几个项目绑在同一个目标下，让日常工作和战略对得上。
- **项目（Project）**——一个有头有尾的交付。比如"上线暗黑模式"。Linear 的建议是：一个项目 1–3 周、1–3 个人，有一个明确负责人（lead）。
- **任务（Issue）**——最小的颗粒。一个 bug、一个小功能、一件事。每个任务属于一个团队，有唯一编号（比如 `ENG-127`）。

打个比方：**倡议是"今年往哪走"，项目是"这两周交什么"，任务是"今天我手里这件具体的事"。**

任务还能再拆成**子任务**；任务之间能标**依赖**（谁阻塞谁）、**重复**、**相关**。团队再按**周期（Cycle，通常 2 周一轮）**从项目里挑任务进来干。

---

## 规划这一层，具体怎么用

三层模型里，"倡议 / 项目 / 周期"是 Linear 最有特色的部分，展开说：

- **项目**有：单一负责人（lead）、协作者（members，自愿收通知）、开始/目标日期、**健康度**（on track / at risk / off track，用颜色标）、进度、估算总量。一个项目还能挂多个**里程碑**，标出关键节点。
- **项目预测图**：项目一旦开始，Linear 会基于你们**每周的交付速度**，预测它大概什么时候能做完，还给出乐观/悲观区间（约 ±40%）。它用一张图把"范围在膨胀吗""能不能按期"摆出来——比口头汇报准。
- **周期**：每轮通常 2 周，可以设冷却期（cooldown，让大家喘口气、还技术债）。每轮有**完成率**（完成的算满分、开始了的算 25%）、一张进度图、以及按历史速度估的**容量**。没干完的自动滚到下一轮。
- **倡议**可以**嵌套**（最多 5 层），用来表示"大目标下面的小目标"，适合做 OKR 式的拆解。

## 干活这一层：一周用下来什么感觉

### 收件箱（Triage）——把噪音挡在正式看板外

Slack 消息、邮件、Sentry 报错、客户工单、外部同事提的需求……这些涌进来的东西不会直接进 backlog，而是先落进团队的 Triage。团队里有人花几分钟过一遍：接受、拒绝、标重复。**队列清清爽爽，正式看板不被噪音污染。**

### My Issues——一打开就知道今天干嘛

不用自己翻。系统按"紧急 → SLA 快到期 → 被阻塞 → 本周该做 → 其它"自动排好，你照着做就行。

### 键盘流——让高手飞起来

建任务按 `C`，改状态按 `S`，改优先级按 `P`，什么都找不到就按 `Cmd+K` 唤出全局命令面板。这套键盘语言是 Linear 的标志。

### 和代码长在一起

你在 PR 标题写 `Fixes ENG-127`，**合并的那一刻，对应任务自动变成"已完成"**。GitHub、GitLab 是一等公民；Sentry 报错、Figma 设计稿能直接挂到任务上。

---

## 文档：spec 文化的一等公民

很多工具把"写文档"当附带功能，Linear 不是——它的整个工作哲学就强调**先写 spec（简短的项目说明），再动手**。所以文档是原生功能：

- 文档挂在**项目、倡议、团队、任务、周期**上，不是孤立的页面。
- **实时多人协作**（看得见别人光标），**版本历史**，**内联评论**可解决。
- 里面能 `@` 引用任何对象（任务、项目、人），贴任务编号会自动关联。
- AI agent 写的内容会**高亮区分**，方便你审。

典型用法：项目立项时写一份 spec（为什么做、做成什么样、怎么验收），后续每周的会议纪要、runbook 都挂在同一项目下。

## 把工作看清：视图和分析

Linear 的"视图"不是固定的列表，而是**你存下来的一个筛选条件**——比如"所有带 bug 标签、分配给我、本周到期的任务"。数据变了，视图自动更新。可以列表、看板、时间线三种摆法；按状态、负责人、项目、优先级等任意维度分组。

**Insights** 是内置分析：周期时长、交付速度、估算准不准、谁手上活最多……把日常填的任务当成**可分析的数据集**，画成图、能导出 CSV。不是给老板看的 PPT，是给团队自己复盘用的。

## 自动化：让工具替你干活

Linear 的自动化分散在几处，思路一致——把"为了工作的工作"砍掉：

- **Triage 规则**：满足某条件的进站任务，自动分配给人 / 打标签 / 进项目。
- **父/子任务自动关闭**：子任务全完成→父任务自动关；父任务关了→剩下的子任务自动关。
- **Git 自动化**：PR 打开→任务进"进行中"；合并→任务进"已完成"。还能按目标分支细分（合到 `staging` 进"测试中"，合到 `main` 进"已部署"）。
- **SLA**：给高优先级任务自动挂截止时间，快到期自动催。
- **陈旧任务自动关闭/归档**：很久没动的任务自动清掉，backlog 不腐烂。

---

## 听见客户的声音

Linear 不只是"内部任务工具"，它把**客户的反馈**接了进来：

- **客户（Customer）是一个实体**：有域名、营收、规模、等级，代表用你产品的公司。
- **客户请求（Customer Request）**：一段来自客户的话，挂在某个任务或项目上。可以直接引用用户的原话，附上来源对话。
- 接 **Intercom / Zendesk / Front** 的客服对话，或 **Slack / 邮件** 进来的反馈，都能自动变成带客户归属的请求。
- **SLA** 让你对客户承诺的响应时间有追踪（比如"严重 bug 24 小时内修"），快违约时火苗图标变红、自动通知。

这让产品决策有了依据——你能看到"哪些需求最多客户在要""大客户的痛点是什么"，而不只是拍脑袋。

## 和编程 Agent（Codex / Claude Code / Cursor）怎么协作

这是 2026 年 Linear 最实用、也最该讲清楚的部分。先说结论：**Linear 没有专门的"Codex 集成"按钮，但有三条官方通道，让任何编程 Agent 都能接进来干活。**

### 三条通道

**1. MCP server（推荐，最省事）**
Linear 官方发布了 **MCP server**（2026 年 2 月上线）。只要你的编程 Agent 支持 MCP——**Codex、Claude Code、Cursor 都支持**——连上之后，Agent 就能直接在你的 Linear 里搜任务、读某个 issue 的完整内容、改状态、加评论、建子任务。不用写代码，配一下连接就行。

**2. API key + GraphQL（最灵活）**
给 Agent 发一把 **Linear API key**（账户安全设置里建，可限定只读 / 只写 / 只能建 issue / 只能评论，还能限到某个团队）。Agent 通过 Linear 的 GraphQL API 或 TypeScript SDK 直接读写。

**3. Agent 当"用户"（Agent 平台，开发者预览）**
更深的整合：把一个编程 Agent 装成 Linear 里的 **"app 用户"**，像普通同事一样能被 @、被分配任务、发评论。你把一个 issue **委派**给它（人仍然是负责人），它就开干。走的是 **Linear for Agents** 平台，目前还是开发者预览，API 会变。

### 一个完整的工作流

1. 你在 Linear 建任务 `ENG-127 上线暗黑模式`。
2. Agent 接手（通过 MCP/API 用你的身份，或作为独立 app 用户被委派）。
3. Agent 读任务 → 在仓库改代码 → 开 PR，标题写 `Fixes ENG-127`。
4. PR 一合并，**Linear 自动把 `ENG-127` 标成"已完成"**。
5. 中间 Agent 还能发评论汇报、拆子任务。

整条链路：**Linear 下任务 → Agent 干活 → 开 PR → 合并自动闭环**。人只审 PR。

### 配套能力

- **Agent Guidance**：在 workspace 或团队级写一段 markdown，告诉所有接进来的 Agent 你的仓库规矩、引用格式、评审流程；Agent 干活时自动收到。
- **怎么盯**：按"委派对象"过滤的视图、按委派切分的 Insights；Agent **不计费席位**。
- Linear 还发了 **AIG（Agent Interaction Guidelines）**——对"Agent 在 Linear 里该怎么表现"的官方建议，自己写 Agent 的人值得看。Agent 不能登录客户端、不能碰管理功能。

## 生态：集成、API、客户端

**集成**：除了 GitHub / GitLab / Slack / Figma / Sentry 这些深度的官方集成，还有 **Intercom / Zendesk / Front**（客服）、**Notion**（文档互链）、**Zapier / Airbyte / Google Sheets**（自动化与数据同步）、**Discord / Loom** 等。集成是 Linear 的强项——PR、Sentry 报错、客户营收都能作为**可查询的属性**存在，不是简单的超链接。

**给开发者的口子**：核心是一套 **GraphQL API**（和它自家 app 用的同一套）+ 强类型 **TypeScript SDK** + **webhook**（数据一变就推给你）+ OAuth 应用。数据一变更实时推给所有客户端。

**客户端**：桌面（Mac / Windows）、网页、iOS / Android、平板 PWA。**实时同步、断网可离线编辑、连上自动合并**。推荐装桌面端——原生通知、常驻、快捷键更顺。

## 权限、安全与合规

- **角色**：工作区 Owner（仅企业版）、Admin、Team Owner、Member、Guest。权限能细到"谁能管标签 / 谁能加人 / 谁能改工作流"。
- **团队是核心单位**：状态、周期、标签、模板都按团队配置；项目可以跨团队共享；**子团队**继承父团队的成员和周期。
- **安全合规**：**SOC 2 Type II、GDPR、HIPAA**（企业版可签 BAA）；传输加密、静态加密。
- **企业能力**：**SAML 单点登录**、**SCIM** 自动开通 / 停用账号、**90 天审计日志**（含 IP、可推给 SIEM）、**数据存美区或欧区**（建工作区时选，不可自助改）、第三方应用需 admin 审批。

## 套餐与价格

Linear 分四档：**Free / Basic / Business / Enterprise**。随档位解锁的关键能力：

| 档位 | 解锁什么 |
|---|---|
| **Free** | 最多 2 个团队，全员 admin，核心功能——小团队试水够用 |
| **Basic** | 更多团队、更多项目——早期小公司 |
| **Business** | **Guest 访客**、**Triage**、**私有团队**、**SLA**、**Asks**（Slack/邮件收需求）、客服集成（Intercom/Zendesk/Front）——开始像"正式在用" |
| **Enterprise** | **Workspace Owner** 角色、**SAML SSO + SCIM**、**审计日志**、**数据区域选择**、第三方应用审批、多 Slack workspace、Salesforce——大公司合规要求 |

> 具体的每席每月价格会随档位和年付/月付变，且 Linear 不时调整，**以 [linear.app/pricing](https://linear.app/pricing) 实时为准**，本文不写死数字以免过时。Agent（AI）不计费席位。

## 和同类比

| 对比 | 一句话 |
|---|---|
| **vs Jira** | Linear 更快、更有主见、为干活的人做；Jira 更灵活、更重、报表和流程更强，适合流程极复杂的大企业。多数嫌 Jira 慢的工程团队迁过来。 |
| **vs Asana** | Asana 是给任何团队（市场、运营、人事）的通用任务管理；Linear 专做软件团队，集成和开发者体验强很多。 |
| **vs Shortcut（原 Clubhouse）** | 最像的对手，定位接近。Linear 更"设计洁癖"、更快、键盘流更强；Shortcut 稍微更灵活一点。 |
| **vs GitHub Projects** | GitHub Projects 免费、贴着仓库、轻量；但缺 Linear 的规划深度（倡议/周期/预测）、客户请求、跨工具集成和独立客户端。 |
| **vs Notion** | Notion 是"文档优先"的通用工作台；Linear 是"任务优先"，文档是它的一个功能而非核心。 |

## 怎么开始用

1. **注册**：用邮箱或 Google 登录，建一个 workspace（工作区）。Linear 推荐**一个组织一个 workspace**。
2. **默认团队**：系统自动建一个和工作区同名的团队，给你一个团队 key（如 `ENG`）。
3. **导入**：从 **Jira、GitHub Issues、Asana** 等用官方导入器迁，或导 **CSV**；也可用 CLI importer 跑脚本。
4. **配集成**：先连 **GitHub/GitLab**（PR 自动闭环）和 **Slack**（消息直接建任务），这两个最先见效。
5. **邀请人**：加同事，按需建更多团队或子团队。
6. **开周期**：在团队设置里启用 Cycle（2 周一轮），开始有节奏。

上手快是 Linear 的卖点之一——多数团队一两天就能跑起来。

## 谁该用、谁别用

**适合：**
- 10–500 人的软件 / 产品团队；
- 工程文化强、追速度、讨厌官僚流程的公司；
- 想从 Jira 迁走、又不想迁到另一个"重型"工具的团队。

**不适合：**
- 需要重型甘特图、资源调度、工时核算的传统项目管理；
- 非软件团队（销售流水线、制造业流程）；
- 喜欢把工具配成"什么都能干"的团队——Linear 故意不给那种自由。

## 常见疑问

- **能自部署吗？** 不能。Linear 只提供云端（美区或欧区），没有自托管版。
- **免费版够用吗？** 个人或两三人的小团队够；团队一多（需要 Triage、访客、SLA）就得升级。
- **能替代 Jira 吗？** 对大多数软件团队能；如果你的流程深度依赖 Jira 的特定字段 / 工作流 / 插件生态，要先评估。
- **有甘特图吗？** 有时间线视图（按项目），但它不是为重型甘特/资源调度设计的。
- **开源吗？** 不开源。客户端是闭源的。
- **数据能导出吗？** 能，CSV / API / 工作区导出，企业版可全量导。

---

## 一句话总结

Linear 是一个**有强烈主见、为干活的人做的、极快、键盘优先**的任务与项目管理工具。它的价值不在功能多，而在**用起来不让人烦**——而它当下正把自己从"给人用的工具"升级成**"人和 AI 协作的协调层"**。
